# Cookbook — 에이전트로 실제로 하는 일

Open Agent OS를 설치한 다음, 무엇부터 하면 되는지 모아둔 레시피 모음입니다. 각 레시피는 **목적 → 이렇게 말하세요 → 에이전트가 하는 일 → 팁** 순서입니다. 예시는 일반적인 상황 기준이니, 그대로 따라 하거나 자기 상황에 맞게 바꿔 쓰면 됩니다.

> 사용 팁: 레시피는 "프롬프트"입니다. 채팅창에 그대로 입력하거나, 자기 말로 바꿔 말해도 됩니다. 에이전트는 도구(메일·위키·검색·일정)를 스스로 조합합니다.

---

## 0. 첫 15분

**첫 대화 열기** — "넌 뭘 할 수 있어?" → 에이전트가 자기 소개와 사용 가능한 기능을 요약합니다.

**첫 기억 남기기** — "이거 기억해둬: 우리 팀 주간회의는 금요일 오후 3시야." → 위키에 기록되고 이후 대화에서 참조됩니다.

**첫 예약 작업 만들기** — "매일 아침 8시에 오늘 할 일 브리핑해줘." → 크론 작업이 등록되고, 다음 날 아침부터 도착합니다.

**첫 파일 보내기** — 사진이나 PDF를 봇에게 보내면 → 읽고 요약하거나 위키에 정리합니다.

**도움 요청** — "이거 어떻게 하는지 docs/faq.md 보고 알려줘." → 에이전트가 문서를 읽고 맞춤 안내를 해줍니다.

## 1. Personal 레시피

### 1-1. 아침 브리핑
- **목적:** 하루를 5분 안에 파악.
- **이렇게 말하세요:** "매일 아침 8시에 브리핑해줘 — 오늘 일정, 답장 필요한 메일, 관심 주제 뉴스 3개."
- **에이전트가 하는 일:** 크론 등록 → 매일 정시에 일정·메일·웹 검색을 모아 한 메시지로 전송.
- **팁:** 처음엔 항목 2개로 시작해 익숙해지면 늘리세요.

### 1-2. 메일 분류와 답장 초안
- **목적:** 받은편지함을 비우는 시간을 줄이기.
- **이렇게 말하세요:** "오늘 온 메일 중 답장 필요한 것만 골라서 요약하고, 상위 3개는 답장 초안 써줘."
- **에이전트가 하는 일:** 메일함을 읽고 우선순위 분류 → 초안 작성(보내기 전 승인 요청).
- **팁:** 발송은 항상 승인 후에만 — 초안만 받고 직접 다듬어도 됩니다.

### 1-3. 지식 기록 (세컨드 브레인)
- **목적:** 흩어진 메모를 자산으로.
- **이렇게 말하세요:** "이거 정리해줘: [회의 메모/아이디어/링크]. 관련 문서와 연결해줘."
- **에이전트가 하는 일:** 위키에 항목 생성 → 기존 문서와 상호참조 → 인덱스 갱신 → 커밋.
- **팁:** 음성 메모로 보내도 됩니다 — 자동으로 글로 바뀝니다.

### 1-4. 위키에 물어보기
- **목적:** "그때 뭐로 결정했더라?"를 즉시 해결.
- **이렇게 말하세요:** "작년 3월에 예산 관련해서 뭘 결정했는지 찾아줘."
- **에이전트가 하는 일:** 위키 전체를 검색해 근거 문서와 함께 답변.
- **팁:** 근거가 없으면 없다고 말합니다 — 추측하지 않게 시키세요.

### 1-5. 리서치와 요약
- **목적:** 조사 시간 단축.
- **이렇게 말하세요:** "X에 대해 조사해서 핵심 5줄로 정리하고 출처 링크 붙여줘."
- **에이전트가 하는 일:** 웹 검색·문서 추출 → 요약(공식 출처 우선, 비공식은 참고 표시).
- **팁:** "공식 문서·원문 기준으로"라고 지정하면 품질이 올라갑니다.

### 1-6. 알림과 팔로업
- **이렇게 말하세요:** "금요일에 Y 챙기라고 알려줘." / "다음 주 화요일까지 회신 없으면 다시 알려줘."
- **팁:** 반복 알림은 크론으로, 일회성은 리마인더로 — 에이전트가 알아서 구분합니다.

### 1-7. 주간 리뷰
- **이렇게 말하세요:** "매주 일요일 저녁에: 이번 주 끝낸 일, 멈춰 있는 일, 다음 주 계획 정리해줘."
- **에이전트가 하는 일:** 위키·메일·일정을 종합해 리뷰 문서 초안 작성.

### 1-8. 파일 처리
- **이렇게 말하세요:** 영수증 사진/계약서 PDF/스크린샷을 보내며 "내용 정리해서 위키에 넣어줘."
- **에이전트가 하는 일:** 텍스트 추출(OCR)·요약 → 분류 → 기록.

### 1-9. 음성으로 쓰기
- **이렇게 말하세요:** 음성 메모 전송 → "방금 메모 정리해서 할 일로 만들어줘."
- **팁:** 이동 중 아이디어·할 일을 남기는 가장 빠른 방법입니다.

### 1-10. 스스로 백업하게 하기
- **이렇게 말하세요:** "매주 일요일 새벽에 너랑 위키 백업하고, 파일 위치 알려줘."
- **에이전트가 하는 일:** 상태 백업 실행 → 산출물 경로 보고.

## 2. Project 레시피 (팀)

### 2-1. 팀 채널 어시스턴트
- **이렇게 말하세요:** Mattermost 채널에서 "이번 주 배포 일정 정리해줘."
- **에이전트가 하는 일:** 채널 맥락 + 위키를 함께 보고 답변. 허용된 멤버만 사용 가능.

### 2-2. 회의록 → 위키
- **이렇게 말하세요:** "회의록 정리해서 위키에 넣어줘: [메모 붙여넣기]"
- **에이전트가 하는 일:** 결정사항·담당자·기한 추출 → 문서 생성 → 관련 프로젝트 문서와 연결.

### 2-3. 주간 팀 리포트
- **이렇게 말하세요:** "이번 주 채널 활동과 미완료 작업 요약해서 보고서 만들어줘."

### 2-4. 공유 문서 검색
- **이렇게 말하세요:** "온보딩 문서가 어디 있고, 첫 주에 뭘 해야 하는지 알려줘." (Outline 연동)

### 2-5. 봇 메일함
- **이렇게 말하세요:** "팀 메일함 확인해서 급한 것만 채널로 올려줘."

### 2-6. 새 멤버 온보딩
- **방법:** 새 멤버의 채팅 ID를 허용목록에 추가(또는 페어링 승인) → 각자 개인 하네스 시딩 진행.

### 2-7. 서비스 점검 도우미
- **이렇게 말하세요:** "서비스 상태 점검하고, 죽은 게 있으면 로그 확인해서 알려줘."

## 3. Company 레시피 (5~50인)

### 3-1. 구성원별 개인 에이전트
- **방법:** 구성원마다 개인 에이전트를 부여하고, 정책으로 허용 도구·행동 범위를 제한.

### 3-2. 권한 인식 지식 검색
- **이렇게 말하세요:** "우리 가격 정책 문서 찾아줘."
- **에이전트가 하는 일:** 권한(ACL)을 지키며 검색 — 볼 수 없는 문서는 답변에 포함하지 않음.

### 3-3. 승인 워크플로
- **방법:** 파괴적·외부 공개 작업은 관리자 승인(JIT) 후 실행. 승인 대기·결과가 기록에 남음.

### 3-4. 감사 확인
- **이렇게 말하세요:** "지난주 팀별 주요 작업 감사 기록 보여줘."

### 3-5. 기존 스위트 연동 (선택)
- **이렇게 말하세요:** "Gmail에 초안 만들어줘 / Notion에 페이지 만들어줘 / Slack에 공지 올려줘." — 연동한 것만 동작.
- **참고:** Google Workspace·Microsoft 365·Slack·Notion은 이미 쓰는 서비스에 연결하는 것 — 추가 구독이 아닙니다.

### 3-6. 모델 라우팅
- **방법:** 민감·고난도 작업은 상위 모델, 일상 작업은 저가 모델로 — 비용과 품질을 함께 관리.

## 4. 운영 레시피

### 4-1. 상태 점검
- **이렇게 말하세요:** "전체 상태 점검해줘." → oaos-ops 체크리스트 실행, 항목별 PASS/FAIL 보고.

### 4-2. 안전한 업데이트
- **이렇게 말하세요:** "백업하고 업데이트한 다음, 점검하고 결과 알려줘."

### 4-3. 봇이 조용할 때
- **이렇게 말하세요:** "봇이 응답을 안 해. 원인 찾아줘." → 게이트웨이 상태·로그 확인 → 원인 보고.

### 4-4. 키 교체
- **이렇게 말하세요:** "키를 교체했어, 새 값이야: [붙여넣기]" → `.env`에 기록, 즉시 검증, 채팅에 재출력하지 않음.

### 4-5. 로그 점검
- **이렇게 말하세요:** "이번 주에 반복되는 오류 있어?"

### 4-6. 용량 점검
- **이렇게 말하세요:** "디스크·메모리 여유 확인하고, 정리할 것 있으면 알려줘."

## 5. 확장 레시피 (문서·자동화)

문서 작업과 반복 업무를 에이전트에게 넘기는 레시피입니다. 익숙해지면 "이 방식을 스킬로 저장해줘"로 나만의 절차로 만들 수 있습니다.

### 5-1. 견적서·인보이스 작성과 발송
- **목적:** 서류 작성·발송에 쓰는 시간 줄이기.
- **이렇게 말하세요:** "이번 주 거래 내역으로 견적서 만들어서 거래처에 보내줘 — 보내기 전에 나한테 확인받아."
- **에이전트가 하는 일:** 표 데이터로 문서 생성 → 파일 전달 → 메일 초안 작성 → **승인 후** 발송.
- **팁:** "전에 보낸 메일 말투로 써줘"라고 하면 기존 메일에서 문체를 맞춥니다. 외부 발송은 항상 승인 후에만.

### 5-2. 메일이 오면 문서 자동 처리 (트리거)
- **목적:** 반복 수신 업무(계산서·신청서 등) 자동화.
- **이렇게 말하세요:** "거래처에서 계산서 메일이 오면 내용 정리해서 기록하고 나한테 알려줘."
- **에이전트가 하는 일:** 메일함 감시(예약 작업) → 내용 추출 → 문서 생성·기록 → 알림.
- **팁:** 처음엔 "알림만"으로 흐름을 확인하고, 익숙해지면 자동 기록을 붙이세요.

### 5-3. 명함·영수증 사진 정리
- **이렇게 말하세요:** 명함 사진을 보내며 "연락처로 정리해줘." / 영수증 "내역 정리해줘."
- **에이전트가 하는 일:** 사진에서 항목 추출(OCR) → 중복 확인 → 연락처·위키에 기록.

### 5-4. 보고서·슬라이드 초안
- **이렇게 말하세요:** "이 내용으로 보고용 슬라이드 만들어줘 — 우리 회사 서식에 맞춰서."
- **에이전트가 하는 일:** 내용 구조화 → 문서·슬라이드 파일 생성 → 수정 반영.
- **팁:** 마음에 드는 서식이 나오면 "이 서식으로 만드는 법을 스킬로 저장해줘" — 다음부터 한 번에 같은 서식으로 나옵니다.

### 5-5. 일정에 맞춘 이동·기상 계산
- **이렇게 말하세요:** "내일 첫 미팅 10시야. 이동 시간 계산해서 출발 시각 알려주고, 기상 알람도 맞춰줘."
- **에이전트가 하는 일:** 일정 확인 → 경로·교통 계산 → 출발 시각과 알람 제안.

### 5-6. 생활 기록과 주간 분석
- **이렇게 말하세요:** "이 사진들 오늘 식단으로 기록해줘." / "이번 주 기록에서 패턴 분석해줘."
- **에이전트가 하는 일:** 사진·메모를 기록 → 주간 요약과 패턴 리포트 작성.

### 5-7. 이중 검증 — 작업 에이전트 + 감사 에이전트
- **목적:** 중요한 문서·숫자의 오류 줄이기.
- **이렇게 말하세요:** "이 문서, 다른 모델로 교차 검증해서 근거 없는 내용과 오류만 보고해줘."
- **에이전트가 하는 일:** 작성에 쓴 모델과 다른 모델로 검증 패스 실행 → 불일치·근거 부족 항목만 보고.
- **팁:** 숫자·계약·공지처럼 틀리면 큰일 나는 문서에 쓰세요. 멀티 LLM 라우팅이 구성된 환경에서 가장 효과적입니다.

- 에이전트에게 새 절차를 가르치고 싶다면: "이 방식으로 하는 법을 스킬로 만들어줘" (또는 `/learn`).
