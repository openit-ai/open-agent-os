# Deployment — Section 5

> v1.6.4 HA 포함 — `deploy/docker-compose.prod.yml` (healthcheck + restart) / `deploy/k8s/` (replicas + probes + PDB). 상세: `docs/ha.md` + `docs/architecture-v1.6.4.md §16.6`.

모든 app 서비스(control-plane :8000, execution-gateway :8001, security :8002)는 `GET /healthz`(liveness), `GET /readyz`(readiness, fail-open — DB/Redis degraded여도 200 유지, `checks` 필드로 상태 노출), `GET /v1/health/detailed`(latency/timestamp 포함 상세) 3종을 노출한다. **HA healthcheck/probe 검증 절차 요약**: Compose에서는 `docker compose -f deploy/docker-compose.prod.yml config | grep -A4 healthcheck`로 healthcheck 정의(`curl -f http://localhost:<PORT>/healthz`, interval 30s, timeout 5s, retries 3, start_period 10s, `restart: unless-stopped`, `depends_on: service_healthy`로 nginx 게이트)를 확인하고 `docker inspect --format '{{.State.Health.Status}}' oaos-control-plane oaos-execution-gateway oaos-security` 및 `curl -f http://localhost:8000/healthz && curl -f http://localhost:8001/healthz && curl -f http://localhost:8002/healthz`(+ `/readyz`, `/v1/health/detailed`)로 3종 엔드포인트를 검증한다; K8s에서는 `kubectl get deployments -n open-agent-os -o wide`·`kubectl get pods -n open-agent-os -o wide`로 `replicas: 2`, `RollingUpdate(maxUnavailable:1,maxSurge:1)`, `livenessProbe /healthz(period 30s, failureThreshold 3 → 90s 후 재시작)`·`readinessProbe /readyz(period 10s, failureThreshold 3 → 30s 후 Endpoints 제외)`, `podAntiAffinity(hostname)`를 확인하고 `kubectl describe pdb -n open-agent-os`·`kubectl get pdb -n open-agent-os`로 `PodDisruptionBudget(minAvailable:1, deploy/k8s/pdb.yaml)` 적용 여부와 `kubectl exec -n open-agent-os deploy/<svc> -- wget -qO- http://localhost:<PORT>/healthz|/readyz`로 Pod 내부 프로브를 검증한다(정상 시 200, draining 중에는 `/readyz`가 `draining` 상태로 readiness 실패 → 트래픽 차단 후 `terminationGracePeriodSeconds:30` 드레이닝). 실패 시 Compose는 `unhealthy` 마킹·자동 재시작, K8s는 liveness 재시작·readiness 트래픽 차단·PDB에 의한 최소 가용성 보장으로 무중단 배포를 유지한다.
